## 1. 무엇을 남기나
| 사건 `kind` | 언제 | 남기는 것 |
| --- | --- | --- |
| `RUN_START`·`RUN_END`·`RUN_ERROR` | 그래프 실행 전체(부모 없는 체인) | 입력·최종 상태의 키 이름, 안전한 값(`step`·`outcome`·`stopped_at`·`has_at_risk_orders`·`visited_nodes`), 처리 시간 |
| `NODE_START`·`NODE_END`·`NODE_ERROR` | 노드 7개(이름 = `langgraph_node`이고 `graph:step:` 태그) | 단계 번호, 바꾼 상태 키, 처리 시간, 오류 종류(`error_code` = 예외 이름). **오류 메시지는 남기지 않음**(2절) |
| `ROUTE` | 갈림길 함수(`route_after_prepare`·`route_from_coordinator`·`route_after_explain`) | 다음 노드 이름 |
| `TOOL_ATTEMPT` | 도구 한 번 시도(`call_with_retry(on_attempt=tracer.tool_attempt)`, GLOW-123) | 도구 이름, 시도 번호, 성공·재시도·실패, 오류 코드, 처리 시간, 단계 |
| `EXPLANATION_ATTEMPT` | 설명 생성 시도(엔진 `generate()`의 `attempts`) | 시도 번호, 검증 오류 코드·위치, 모델, 프롬프트 판(`explain_ready_v1@1.0.0`), 토큰 수(NFR-008) |

- **공통 칸:**
  - 사건 ID: `uuid5(실행 ID, 순번)`. 다시 보내도 중복이 생기지 않습니다.
  - 추적 ID: 실행 ID(서비스가 만든 UUID)
  - `analysis_run_id`·`company_id`·순번·시각(UTC)
- **그래프는 고치지 않습니다.** `graph.ainvoke(state, config={"callbacks": [tracer.callback_handler()], "configurable": {...}})`처럼 콜백 하나만 넘깁니다.

```python
tracer = build_run_tracer(
    run_id, company_id, [TraceOutboxSink(base_dir)]
)  # 자동 추적이 켜져 있으면 TraceConfigError
try:
    result = await graph.ainvoke(
        state, config={"callbacks": [tracer.callback_handler()], "configurable": {...}}
    )
finally:
    await (
        tracer.aclose()
    )  # 루프를 막지 않고 쓰기를 최대 2초 기다림. 그래프가 예외를 내도 닫힘
```

## 3. 기본 꺼짐과 내부 로그
- **LangSmith 전송기는 두지 않았습니다.** 업무 데이터 외부 전송 승인(8.1 운영 확인 항목) 전이기 때문입니다. 승인되면 같은 `TraceSink` 모양(`write(event)`)으로 전송기를 더하고, 실패분은 내부 로그에서 다시 보냅니다.
- **자동 추적 차단:** `LANGSMITH_TRACING`·`LANGSMITH_TRACING_V2`·`LANGCHAIN_TRACING_V2`·`LANGCHAIN_TRACING` 중 하나라도 켜져 있으면 LangChain이 그래프 상태를 **마스킹 없이** 보냅니다. 그래서 `build_run_tracer`가 `TraceConfigError`로 멈춥니다.
- **내부 로그:** `<base>/agent_trace_outbox/<company_id>/<YYYY-MM-DD>.jsonl`(UTC 날짜). 사건 하나가 JSON 한 줄이고, 여러 실행이 동시에 써도 줄이 섞이지 않습니다(잠금). `base`는 앱 실행기가 설정 `AGENT_TRACE_DIR`로 넘깁니다(이슈 #51, `run_start/app_runner.py` `build_tracer_factory`). 비우면(기본) 추적하지 않습니다. 배포 컨테이너에 쓸 수 있는 폴더가 정해지기 전이라 기본을 비워 둔 것이고, 이때는 agentflow 8.1 "외부 전송 불허 시 내부 서버 로그에 전량 저장"과 다릅니다(폴더를 넣으면 같음). 싱크 하나를 모든 실행이 같이 씁니다(줄 잠금이 싱크마다). 파일 날짜는 사건의 서버 시각(UTC)이고 가상 시각을 쓰지 않습니다. `~`·상대 경로는 설정을 읽을 때 절대 경로로 바꿉니다(엔진 경로와 같은 규칙, 상대 경로는 서버를 띄운 폴더 기준). 자동 시작을 켰을 때 폴더를 넣었는데 쓸 수 없으면 서버 시작이 멈춥니다(`docs/analysis/auto-start.md` 7절). 이 확인은 `<폴더>/agent_trace_outbox`를 만들고 임시 파일을 하나 써 본 뒤 지웁니다. 폴더·파일은 서버 실행 사용자의 기본 권한으로 만들어지므로, 배포에서 폴더를 정할 때 "개발·운영 담당만 접근"(agentflow 8.1)에 맞게 권한도 정합니다. 서버 프로세스가 둘 이상이면 줄 잠금이 프로세스마다라 같은 파일에 동시에 쓸 수 있습니다(자동 시작의 "서버 프로세스 하나" 전제).

## 4. 추적 장애 독립성
- 분석 쪽(콜백·훅)은 사건을 만들어 줄에 넣기만 합니다. 쓰기는 실행마다 하나인 쓰기 스레드가 합니다. 그래서 기록이 느려도 분석이 기다리지 않습니다.
- 쓰기 예외·마스킹 예외·콜백 예외는 모두 잡아서 세기만 합니다(`sink_failures`, 경고 로그). 분석 상태·재시도 횟수·실패 요약·결과는 바뀌지 않습니다.
- **async 코드에서는 `await tracer.aclose(timeout)`**로 닫습니다(스레드에서 기다림). 동기 `close(timeout)`를 이벤트 루프에서 바로 부르면 쓰기가 밀렸을 때 루프 전체가 최대 `timeout`초 멈춥니다. 그러면 같은 루프의 다른 실행의 도구가 시간 초과로 기록되고 재시도를 씁니다(PR #42 리뷰 재현). 둘 다 시간이 지나면 기다리지 않고 넘어갑니다(남은 쓰기는 뒤에서 계속됨).
- **돌다가 쓰기가 막히면(디스크 가득·권한 바뀜):** 분석은 그대로 끝나지만 사건마다 경고 한 줄(스택 포함)이 남아, 실행 하나에 수십 줄이 쌓입니다(실제 묶음 실행 1건 = 사건 약 43건). 시작 확인은 시작 때 한 번만 봅니다. 첫 실패만 스택을 남기고 나머지는 세는 방식은 후속입니다.
- `explanation_attempts`도 예외를 올리지 않습니다(엔진과 다른 모양이면 세기만 함).

## 5. 시험 (26건, 매개변수 포함)
| 시험 | 내용 |
| --- | --- |
| 처음부터 끝까지 | 뼈대 그래프 실행 하나에서 `RUN_START` → 노드·갈림길 → `RUN_END(outcome)`. 노드 순서 = 그래프의 `visited_nodes`, 순번 연속, 모든 사건의 실행·고객사·추적 ID가 같음 |
| 사건 ID | 같은 실행을 두 번 돌려도 사건 ID가 같고, 실행 안에서는 겹치지 않음 |
| STALE·오류 | STALE이면 조정 에이전트 노드에서 멈춘 것이 남음. 상태 조회 오류는 도구 밖 예외라 노드가 `FAILED`로 끝내고(이슈 #57 1번) 그 노드 끝·`RUN_END`에 `outcome: FAILED`·`step`·`<노드>:failed`만 남음(오류 종류는 추적에 없고 서버 로그에 있음). 그래프 밖으로 나가는 오류(실행 도구 묶음 연결 실수 `RuntimeWiringError` 등)는 `NODE_ERROR`·`RUN_ERROR`로 남고 **오류 종류만 있음**. **어느 쪽이든 오류 메시지는 기록에 없음**(접속 문자열·비밀번호·토큰이 기록에 없음) |
| 마스킹(리뷰 반영) | 조사가 붙은 주문 코드·앞에 공백 없는 코드·overlay 실제 문장(`…B-ORD-99999999-9999이 중복되었습니다`)·형식 밖 키·조사가 붙은 이메일 5가지를 **끝자리까지** 가림. 판 번호·`코드@위치`는 남음 |
| 루프 막지 않기(리뷰 반영) | 쓰기가 1.2초치 밀린 상태에서 `aclose(0.4)` 동안 다른 작업이 계속 돎. 같은 일을 동기 `close`로 하면 그동안 멈춤(시험 안 음성) |
| 설명 시도 모양 | `codes`가 `None`이면 OK로 남기고, 풀 수 없는 모양이면 예외 없이 세기만 함 |
| 재시도 훅 | `AttemptRecord`와 같은 칸(대역 객체)으로 재시도 → 성공이 `RETRY`·`OK`로 남음. **실제 `call_with_retry`(GLOW-123, #28 머지)**에 `on_attempt=tracer.tool_attempt`를 넘겨 일시 오류 1회 → 성공이 `RETRY(TOOL_TEMPORARY_ERROR_EXHAUSTED)`·`OK`로 남음 |
| 설명 시도 | 오류 코드·판 번호·토큰 수는 남고, 프롬프트 원문·모델 출력 원문은 없음 |
| 장애 독립성 | 쓰기가 예외를 내도 결과가 추적 없이 돌린 것과 같음. 쓰기가 사건마다 0.2초 걸려도 분석은 기다리지 않음(나중에 다 씀). 마스킹이 깨져도 예외가 나가지 않음 |
| 마스킹 | 주문 코드·이메일 가림, 같은 실행 같은 값, 다른 실행 다른 값. 금지 칸 제거와 수·판 번호 유지. 길이 제한 |
| 기본 꺼짐 | 자동 추적 환경 변수 4개 각각 `TraceConfigError`. 이 저장소의 시험 환경에서 자동 추적이 꺼져 있음 |
| 내부 로그 | 사건마다 한 줄, 경로·날짜, 원래 주문 코드 없음. 실행 4개가 동시에 200줄을 써도 줄이 깨지지 않음 |
| 통합(DB) | 실제 실행 상태 조회기(`AnalysisRunStatusReader`)로 overlay STALE 실행을 돌려 `prepare` → `coordinator`에서 멈춘 것이 내부 로그 마지막 줄(`RUN_END`, `STALE`)까지 남음 |

- **음성 시험(11-05):** 아래를 일부러 바꿔 각각 시험이 실패하는 것을 확인했습니다.
  - 주문 코드 마스킹을 끄면 3건 실패
  - 쓰기 예외 세기를 빼면 장애 독립성 시험 실패
  - 쓰기를 분석 쪽에서 바로 하면 느린 기록 시험 실패
  - 실제 재시도 시험에서 `on_attempt`를 빼면 실패
  - (리뷰 반영) 주문 코드 `re.ASCII`를 빼면 3건 실패, `aclose`를 동기 `close`로 바꾸면 루프 시험 실패, 설명 시도의 예외 잡기를 바꾸면 모양 시험 실패, 오류 메시지를 다시 남기면 오류 시험 실패. 이메일은 `re.ASCII` 없이 조사 붙은 주소를 0건, 있으면 1건 잡음을 따로 확인

## 7. 작업 중 실패와 결정
- **PR #42 리뷰 크리티컬 2건(11-05, euncheol-kim):**
  - Python 정규식의 `\b`·`\w`는 기본으로 한글도 단어 글자로 봅니다. 그래서 코드·이메일 바로 뒤에 조사가 붙으면 가리지 못했습니다. 제 시험 문장은 모두 뒤에 공백이 있어 드러나지 않았습니다. `re.ASCII`와 넓힌 주문 코드 형식으로 고치고, 오류 메시지는 아예 남기지 않게 했습니다.
  - 처음 고친 시험은 "`-ORD-`가 남았나"만 봐서, 정규식이 뒤로 물러나 앞부분만 가리고 끝자리(`-0040`)를 남기는 경우를 통과시켰습니다(음성 시험으로 찾음). 원래 값과 끝자리가 모두 사라졌는지 보도록 바꿨습니다.
  - `close()`는 동기라 async 코드에서 부르면 루프를 멈춥니다. 제 시험은 `close`를 0.05초로만 불러 못 잡았습니다. `aclose()`를 두고 문서 예시를 `try/finally` + `aclose()`로 바꿨습니다.
- **칸 이름 필터가 너무 넓었음(11-05):** 처음에는 칸 이름에 `prompt`·`token`이 들어가면 모두 지웠습니다. 시험에서 판 번호 `prompt_version`이 지워졌고, 토큰 수 `input_tokens`도 지워질 상황이었습니다. 프롬프트 원문 칸과 인증 토큰 칸만 지우는 패턴으로 좁혔습니다.
- **이메일 패턴이 판 번호를 가림(11-05):** `explain_ready_v1@1.0.0`이 이메일 모양으로 잡혔습니다. 도메인 끝이 글자(TLD)일 때만 이메일로 봅니다.
- **고치다 넣은 백스페이스 문자(11-05):** 셸에서 정규식을 바꾸다 `\b`가 실제 백스페이스 문자로 들어가, 이메일을 하나도 못 잡았습니다. 시험이 잡았고, 파일 전체에 제어 문자가 없는지 확인했습니다.
- **LangSmith 설정을 넣지 않음:** 켜기·끄기 설정을 `config.py`·`.env.example`에 두려 했지만, 전송기가 승인 전이라 쓸 곳이 없고 두 파일은 다른 PR과 겹치는 공용 파일이라 뺐습니다.
